# AutoJuben SaaS v0.6.0：Vercel + Supabase 部署指南

**部署之前必须通过本地构建和 CI；本源码包未经真实 Stripe/Supabase 联调，不应直接启用收款。**

## 1. 上传 GitHub

解压后进入包含 `package.json`、`vercel.json`、`apps`、`api` 和 `sql` 的最外层项目目录。确保 `.env` 未上传。

```bash
npm install
npm run quality
npm run typecheck
npm test
npm run build:web
```

首次安装后把 `package-lock.json` 提交到 GitHub，然后把 `.github/workflows/quality.yml` 的安装命令改为 `npm ci`，以后依赖版本可复现。创建 GitHub Private 仓库，把**项目根目录**推送到仓库。

## 2. Supabase 数据库

打开 https://supabase.com/dashboard 创建 `autojuben-saas` 项目。

- 新数据库按顺序运行：`sql/001_initial.sql`、`002_launcher_port.sql`、`003_supabase_vercel.sql`、`004_customer_portal_payments.sql`、`005_api_quality.sql`，然后运行 `007_provider_api_routes.sql`（上游视频 API 路径与鉴权模式配置）。`006_script_storyboard.sql` 是独立的剧本/分镜迁移草案，审批与验证前不执行。
- 如果已经部署过 v0.5.0，请先做数据库备份，然后**只执行 `sql/005_api_quality.sql`**。不要清空现有数据库。
- Storage 创建**私有** bucket：`autojuben-media`。
- Authentication 启用 Email 登录；后续将站点 URL 和密码重置回调配置到正式 Vercel 域名。
- 顶部 Connect → Transaction pooler，复制完整的 `DATABASE_URL`，不要猜地址。

## 3. Vercel 新建项目

访问 https://vercel.com/new ，Import GitHub 私有仓库，配置：

| Vercel 选项 | 值 |
|---|---|
| Framework | Vite |
| Root Directory | `./` |
| Build Command | `npm run build:web` |
| Output Directory | `apps/web/dist` |
| Install Command | `npm install`（有 lockfile 后改为 `npm ci`） |
| Node.js | 22.x |

Vercel Settings → Environment Variables 配置 `.env.example`：

- 后端：`DATABASE_URL`、`SUPABASE_URL`、`SUPABASE_PUBLISHABLE_KEY`、`SUPABASE_SECRET_KEY`、`SUPABASE_STORAGE_BUCKET=autojuben-media`、`ENCRYPTION_KEY`、`CRON_SECRET`。
- 前端公开值：`VITE_SUPABASE_URL`、`VITE_SUPABASE_PUBLISHABLE_KEY`。
- 登录和环境：`PUBLIC_ORIGIN=https://真实域名`、`PLATFORM_ADMIN_EMAILS=管理员邮箱`、`MOCK_VIDEO_PROVIDER=true`、`ALLOW_INSECURE_VIDEO_HTTP=false`。

**任何 SECRET_KEY、数据库密码、Stripe Secret 不准使用 VITE_ 前缀，也不能放到前端源码中。** 修改环境变量需要重新部署。

## 4. 上线后检查

1. `https://真实域名/healthz` 有 `ok: true` 与 `version: 0.6.0`。
2. `/app` 测试注册、登录、密码找回、History、购买记录。
3. `/admin` 测试管理员用户搜索、订单、API 设置和 API 质量指标。
4. 用户 Settings → API Access，生成 `read` API Key，使用页面上的 REST、JSON 例子进行查询；撤销后确认无法继续使用。
5. 验证两个不同工作区之间读写隔离，不能靠换 `orgId` 看别人的数据。
6. 先模拟生成视频；真正对接 151 API 时要求对方提供 HTTPS，不能默认通过 HTTP 传卡密。
7. Stripe 必须先用 `sk_test_` 完整验证 Checkout、Webhook、积分入账、部分/全额退款；确认后再启用收款开关。
8. 配置 Supabase Cron，使用 `setup/supabase_cron.sql`，修改为真实 URL，并把密钥妥善存到 Vault/环境变量。

## 三个 API 地址

- GraphQL：`POST https://你的域名/graphql`（登录会话）
- RESTful：`GET/POST/PATCH/DELETE https://你的域名/api/v1/...`（会话或工作区 API Key）
- JSON 命令：`POST https://你的域名/api/json`，例如 `{"operation":"projects","params":{"orgId":"UUID"}}`。

详细操作、请求/响应格式和安全约束见 `docs/api-protocols.md`，完整 REST 路由在 `docs/openapi.json`。
